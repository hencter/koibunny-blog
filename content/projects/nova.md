Nova 是一个**自举式个人知识库**：库本身由 AI 代理维护，人只负责对话。
摄入新知识、交叉链接、健康检查、提交历史——这些动作全部由代理在仓库内完成。

它不是一个应用，而是一套**约定 + 技能 + 目录契约**。克隆下来用 Codex 或 OpenCode 打开，
代理就按同一套规则继续维护它。

## 目录即契约

```
AGENTS.md            代理在仓库内必须遵守的规则（约 29 KB）
_identity/           与「我是谁」相关的长期事实（6 个文件）
_meta/               库自身的元信息（3 个文件）
concepts/            原子概念笔记，29 篇，靠 [[]] 双链连成图
tools/               每个代理运行时一篇笔记：Codex / OpenCode / Cursor / Copilot / Aider
patterns/            可复用工作流模式，5 篇
templates/           新笔记的骨架，3 个
conference.md        多代理协作协议的落点
log.md               追加式的操作日志，同时是初始化判据
```

`concepts/` 是这张图的节点，`tools/` 那 8 篇则回答一个很具体的问题：
**同一个知识库，换一个代理运行时，规则要不要改？** 答案是内核不变、适配层换掉。

## 双运行时：同一内核，两套适配

仓库现在有两份，区别只在运行时约定的目录名：

| | Codex 版 | OpenCode 版 |
| --- | --- | --- |
| 技能目录 | `.agents/skills/` | `skills/` |
| 运行配置 | `.codex/` | `opencode.jsonc` |
| 技能数量 | 4 | 4 |

四个技能是同一组：`nova-kb`（库维护主流程）、`auto-commit`、
`beauty-selfie-prompt-engine`、`beauty-male-prompt-engine`。

{{< callout type="tip" title="这一层为什么值得单独抽出来" >}}
把「知识怎么组织」和「哪个代理来操作」分开之后，换运行时只需要换一个目录名和一份配置文件。
反过来，如果把代理专属的路径写进正文笔记里，库就被某一个运行时锁死了。
{{< /callout >}}

## 初始化兜底

别人克隆走的库，不能带着原主人的身份继续跑。Nova 用两个触发器强制进入初始化问答：

1. `log.md` 里没有任何历史条目 —— 全新仓库；
2. `user-config.md` 里 `owner_name` 仍是 `"未设置"` —— 库是旧的，但身份没配。

任一条件成立就问：`Nova: 你想叫我什么名字？`
第一个条件覆盖「从没跑过」，第二个条件覆盖「跑过但换了人」。
只留一个都不够：只判断日志会漏掉「复制目录」这种克隆方式。

## 持久化就是提交

代理每完成一轮维护就提交一次，提交信息写清改了什么。
这样做的收益不在「有版本控制」，而在于：

- **记忆落在 git 里**，而不是某个会话的上下文里。换代理、换机器、隔半年回来，读提交历史就能接上。
- **每一步都可回滚**。代理写错一篇笔记时，回滚的粒度是一篇，而不是整库。

代价是提交频率高、需要额外防住密钥与私人内容入版本库。
`user-config.md` 这类带个人信息的文件是靠 `.gitignore` 挡住的，不是在提交时过滤——
过滤晚一步，密钥就已经进了历史。
